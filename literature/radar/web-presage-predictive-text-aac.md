# Presage — intelligent predictive text entry system with n-gram and recency predictors

## Why on radar

The AAC PWA (brainstorm session `notes/brainstorm/2026-07-25-the-boys/2026-07-25-the-boys.md`) requires a word-prediction grid populated from context (current prefix + prior tokens). The brainstorm chat explicitly named Presage as a candidate: "Existing AAC corpora and predictive-text libraries (e.g. `presage`, or simply an n-gram LM over the user's own utterance history) cover this." Presage is relevant for three reasons:

1. **Language-agnostic training**: its `text2ngram` tool builds an n-gram SQLite database from any text corpus, so an Afrikaans corpus (e.g. GoVZA government text, NCHLT corpus, user's own utterance history) can be fed directly in without modifying the engine.
2. **Offline, on-device execution**: runs entirely locally in C++ (no network dependency), which aligns with the PWA's offline-first design requirement.
3. **Recency predictor built-in**: the Recency predictor implements exponential-decay probability weighting over recently used tokens — structurally equivalent to the decay-weighted phrase-bank scoring discussed in the brainstorm — meaning the engine already models session vocabulary drift without requiring custom implementation.

**Resolution (2026-07-25):** No WASM port of Presage exists and none is practical without significant porting effort (C++ SQLite file I/O is incompatible with the browser sandbox). Presage is therefore **not usable browser-natively**. The browser-native replacement is `predictionary` (AsTeRICS AAC project, npm) — see `web-predictionary-js-word-prediction.md`. Presage remains relevant as a reference architecture and for offline-native deployments (Termux/Python), but is not the Phase 1 implementation choice.

## Summary

Presage (formerly Soothsayer) is a C++ predictive text entry library developed by Matteo Vescovi. It models natural language as a combination of redundant information sources and merges predictions from multiple pluggable predictor modules, each implementing a different algorithm. The primary predictors are: (1) a generalised smoothed n-gram predictor using a SQLite language model generated by the included `text2ngram` tool; (2) an ARPA predictor supporting Katz backoff smoothing; (3) a recency predictor assigning exponentially decaying probabilities to recently typed tokens; (4) a dictionary (prefix-completion) predictor; and (5) an abbreviation-expansion predictor. The architecture is plugin-based and XML-configured, allowing different predictor combinations and weights at runtime. Bindings exist for C, C++, Python, .NET/C#, and via D-Bus/WCF services for other languages. The system supports online learning (incremental update as the user types) and offline learning (batch training on a text corpus). It is cross-platform (Linux, Windows, macOS, Android, iOS, Maemo) and GPL-licensed. Latest release: 0.9.1.

## Key claims

- **Afrikaans training is straightforward**: the `text2ngram` tool generates language models from any text corpus, regardless of language. The Sailfish OS keyboard fork documents the process: split text into words, generate all n-grams, count occurrences, output to SQLite. An Afrikaans corpus (GoVZA, NCHLT, or user utterance history) can be piped directly. No language-specific code changes are required.
- **Recency predictor matches the brainstorm scoring function**: the Recency predictor "assigns exponentially decaying probability values to previously encountered tokens… tokens are assigned a probability value that decays exponentially with their distance from the current token." This is functionally identical to the exponentially weighted moving-average score `s(p, t_now) = Σ e^{-λ(t_now - t_i)}` discussed in the brainstorm for the quick-phrase bank. The half-life parameter λ is configurable.
- **N-gram smoothing formula**: the primary predictor computes `P(w3 | w1, w2) = a·f(w3|w1,w2) + b·f(w3|w2) + c·f(w3)` where a, b, c are configurable linear interpolation weights and f(·) values are corpus-count ratios. This is standard linear-interpolation smoothing — a well-understood, computationally cheap technique suitable for constrained devices.
- **Online + offline learning**: online learning dynamically updates predictor state as context changes (session-level adaptation); offline learning trains from a provided text body (corpus-level). Both are configurable and independently toggleable via the `ONLINE_LEARNING` config variable.
- **ACAT (Intel Labs) production use**: Presage provides the predictive text component for ACAT, originally developed for Stephen Hawking. The WCF service integration (Windows Communication Foundation named-pipe transport) is the architecture used there. This establishes Presage as production-grade AAC software, not just a research prototype.
- **Python binding available**: `import presage; prsg = presage.Presage(config); prsg.predict(string)` — the full API is SWIG-wrapped. This enables rapid prototyping and corpus pipeline scripting within the `afrikaans-aac` conda environment.
- **No WASM port exists — blocker confirmed (2026-07-25)**: no npm package, Emscripten build, or WASM deployment of Presage exists. The C++ SQLite file I/O is fundamentally incompatible with the browser sandbox without significant porting work (mapping filesystem calls to OPFS). Presage is therefore **not browser-native** and not the Phase 1 implementation choice.
- **Browser-native replacement identified**: `predictionary` (npm, AsTeRICS AAC project) is the resolved alternative — pure JS, zero dependencies, self-learning, serialises to JSON for IndexedDB persistence. See `web-predictionary-js-word-prediction.md`.
- **Presage remains relevant for**:
  - Native Android deployment via Termux + Python binding (full trigram + recency, no browser constraint)
  - Reference architecture: Presage's predictor design (smoothed n-gram + recency decay) is the conceptual model that `predictionary` partially implements, and is worth citing as prior art if the methodology section describes the prediction subsystem
- **Sailfish OS keyboard fork is the most actively maintained variant**: `sailfish-keyboard/presage` fork documents corpus preparation, n-gram database generation, and language-specific tokenisation adjustments. This fork is the best reference for Afrikaans corpus integration.
- **D'Albis et al. paper**: Presage documentation links to "A Predictive Speller for a Brain-Computer Interface based on motor imagery" (Politecnico di Milano). This paper uses Presage as the language prediction module in a BCI AAC system — a close analogue to the current use case. The PDF is available at `presage.sourceforge.io/documentation/papers/dalbis.pdf` and may be worth retrieving as formal literature supporting the Presage integration design.
- **License**: GPL v2 or later. The Python binding is GPLv2+. An application that dynamically links `libpresage` inherits GPL obligations; a service architecture (prediction server called via HTTP/socket) may provide isolation.

### Smoothed n-gram predictor formula (from features page)

```
P(w3 | w1, w2) = a * f(w3 | w1, w2) + b * f(w3 | w2) + c * f(w3)

where a, b, c are configurable smoothing parameters and:
  f(w3 | w1, w2) = C(w1, w2, w3) / C(w1, w2)
  f(w3 | w2)     = C(w2, w3) / C(w2)
  f(w3)          = C(w3) / C
  C(w0...wn)     = count of n-gram <w0,...,wn> in corpus
  C              = sum of all token counts
```

This is standard linear interpolation (Jelinek-Mercer smoothing). For a 3-gram model trained on an Afrikaans corpus, this gives context-aware word completion after as little as two prior tokens.

### Corpus pipeline for Afrikaans (from Sailfish OS fork documentation)

```bash
# 1. Obtain Afrikaans text corpus (e.g. GoVZA, NCHLT, or user utterance log)
# 2. Generate 1-, 2-, 3-gram database
text2ngram -n 1 -o af_1gram.db -f sqlite corpus.txt
text2ngram -n 2 -o af_2gram.db -f sqlite corpus.txt
text2ngram -n 3 -o af_3gram.db -f sqlite corpus.txt

# 3. Configure presage to use the database files via XML config
# 4. Run predictor: prsg.predict("goeie") → ["môre", "dag", "naand", ...]
```

Note: the Sailfish fork recommends cleaning the corpus before n-gram generation (remove non-language characters, normalise whitespace, language-specific tokenisation rules).

### Python binding quickstart

```python
import presage

# Config XML string (can also be a file path)
config = """<presage><ProfileManager>...</ProfileManager></presage>"""
prsg = presage.Presage(config)

# Predict next word given context
predictions = prsg.predict("goeie ")  # → list of strings, highest probability first
```

### WASM integration assessment (resolved 2026-07-25)

No WASM port of Presage exists and none is planned. The C++ SQLite file I/O requires mapping to the browser's Origin Private File System (OPFS), which is non-trivial porting work with no upstream effort behind it.

**Resolved**: the browser-native replacement for Phase 1 is `predictionary` (npm, AsTeRICS AAC project). See `web-predictionary-js-word-prediction.md` for full details.

Presage remains the reference for the **native/sidecar path** if richer trigram context is needed in a later phase:

- **Python sidecar via Termux** (Android-only): install Termux + Python + `libpresage` Python binding; expose predictions over a local HTTP socket; the PWA calls `localhost:PORT/predict?prefix=goe`. Full trigram + recency predictor, Afrikaans corpus via `text2ngram`. Adds ~10 minutes provisioning and a Termux dependency.
- **Offline Cloudflare Worker** (not viable): n-gram predictions require the SQLite database locally; a Worker cannot hold the database state between requests at acceptable cost.
